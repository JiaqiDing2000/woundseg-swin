FINAL-B CODE

Run the commands below from the repository root. Python 3.10 was used for
training and for the release checks. The original runtime used PyTorch
2.6.0+cu124 and torchvision 0.21.0+cu124.

Environment
-----------
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install torch==2.6.0 torchvision==0.21.0 --index-url https://download.pytorch.org/whl/cu124
python -m pip install -r requirements.txt

For CPU inference, install the same torch/torchvision versions from the
https://download.pytorch.org/whl/cpu index instead of cu124. Training requires
a CUDA GPU. No segmentation-models-pytorch, transformers, GUI or YOLO package
is needed to run this final-model release.

Data and weights
----------------
The extracted release assets must produce these paths:
  datasets/internal/dataset_manifest.json
  datasets/internal/train/<image> and <image>_mask.png
  datasets/internal/valid/<image> and <image>_mask.png
  datasets/internal/test/<image> and <image>_mask.png
  weights/seed_1001.pth ... weights/seed_1006.pth

The dataset contains 286 / 30 / 35 image-mask pairs. Class IDs are:
0 Background, 1 Epithelial, 2 Granulation, 3 Necrotic, 4 Pus; 255 is ignored.
train.py and evaluate.py verify the dataset membership and file hashes.
The recorded split was adjusted during model development; its provenance
is retained in the dataset manifest.

Benchmark evaluation
--------------------
python src/evaluate.py --checkpoint weights/seed_1005.pth --split test --device cpu --output outputs/seed_1005_test.json
python src/evaluate.py --checkpoint weights/seed_1005.pth --split valid --device cuda --output outputs/seed_1005_valid.json

For all six seeds:
for seed in 1001 1002 1003 1004 1005 1006; do
    python src/evaluate.py --checkpoint "weights/seed_${seed}.pth" --device cuda --output "outputs/seed_${seed}_test.json"
done

This reproduces the segmentation benchmark: a square ROI is determined
from the reference mask, expanded by a factor of 1.4, clamped to the image,
and resized/padded to 256 pixels. Predictions and metrics are in that ROI.
These results are distinct from full-image, annotation-free inference.
JSON metric values are fractions; multiply by 100 to express percentages.
The confusion matrix uses true classes as rows and predicted classes as
columns. Published mean and sample SD use the six per-seed metric values.

Image-only prediction and wound area
-----------------------------------
python src/predict.py --image example.jpg --checkpoint weights/seed_1005.pth --mode area --output outputs/example_mask.png --device cuda

With a measured 30-mm ruler span of 143.0834051166558 pixels:
python src/predict.py --image example.jpg --mode area --output outputs/example_mask.png --ruler-length-px 143.0834051166558 --ruler-length-mm 30 --device cuda

Replace the example image and pixel span with the actual photograph and
its calibration. The output PNG contains class IDs; the adjacent JSON
contains pixel counts, model/image checksums and the calibrated area.
Without --ruler-length-px, pixel counts are reported without physical area.
The formula is foreground_pixels * (ruler_length_mm / ruler_length_px)^2.
All four foreground classes and all connected components are retained.

Modes:
  global        Aspect-preserving full-image letterbox at 256 pixels.
  global-tiles  Global probabilities plus native 512-pixel tiles, with
                25% overlap, each tile resized to the model's 256-pixel
                input. The two probability contributions have equal weight.
  area          The global-tiles workflow plus the original UI orientation
                rule: if the initial predicted foreground bounding box is
                taller than it is wide, predict again after a 90-degree
                clockwise rotation and restore the saved mask orientation.

The published final-B area workflow used mode area and seed 1005, selected
by the highest recorded validation mIoU among six final-B seeds. Images
are read with OpenCV, matching the original UI. No reference mask or manual
area measurement determines the model input or segmentation.

Training
--------
python src/train.py --seed 1005 --output outputs/retraining --workers 8

For a sequential six-seed run:
for seed in 1001 1002 1003 1004 1005 1006; do
    python src/train.py --seed "$seed" --output outputs/retraining --workers 8
done

The first training run downloads the ImageNet-pretrained timm encoder.
Checkpoint evaluation and prediction load the released state directly and
do not download pretrained weights.

The recipe in configs/final_b.json records ASPP rates 1/2/3, class-weighted
CE plus Tversky, and image sampling with 40% uniform plus 20% each for
granulation, necrotic and pus pools. Eligible images contain at least 328
pixels of the target tissue in the unaugmented training ROI. Sampling is
with replacement and is equal per eligible image within each pool.

The original FP32 loop, augmentations and initialization order are retained:
batch size 4, gradient accumulation 2, maximum 100 epochs, early stopping
after 20 epochs without validation-mIoU improvement, AdamW at 1e-4,
5 warmup epochs followed by cosine decay, gradient-norm clipping at 5.
The recorded recipe is fixed by the code; final_b.json is its readable
configuration record, not an unrestricted hyperparameter interface.
Reusing an output folder with a best checkpoint skips that training run.
Use a new output folder for a fresh run.

Model checkpoints include model, optimizer and scheduler state. The best
checkpoint is chosen by validation mIoU; the test subset is evaluated after
training. Deterministic flags, worker seeding and the sampler generator
are preserved. Exact retraining may depend on hardware and dependency
versions; the supplied checkpoints reproduce the recorded evaluation.

Source and verification
-----------------------
src/historical.py retains the model, preprocessing, metrics and training
functions from the recorded W41 source used by W70. Unused baseline code
was removed. src/final_b.py applies the recorded final-B loss, sampling and
ASPP attributes. Image-only preprocessing and tiling are retained from
the functions used by the final-B area analysis.

environment/source_provenance.json lists source hashes and portability
changes. environment/runtime_versions.json records the checked packages.
environment/release_verification.json summarizes comparisons against the
recorded model results. No full retraining was performed during packaging.
